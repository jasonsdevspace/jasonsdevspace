## How I Like to Work

- Favor **clarity over cleverness**.
- Design for **change and extension**, not just the happy path.
- Use **tests and types** to keep refactors safe.
- Automate what I can with **scripts and CI**.
- Communicate via **docs and small, focused commits**.
- Build for **accessibility** from the start: keyboard first, audited in CI, Lighthouse at a hundred before it ships.

## How I Lead

- Make architectural decisions **explicit and reversible**, written up as **decision records** rather than settled in long debates.
- Review with the same three questions: what breaks, what gets slower, what gets simpler.
- Run 1:1s for the engineer, not the status report.
- Remove ambiguity before it compounds, and protect the team from interrupts.
