## How I work

- **Clarity over cleverness**, in code and in conversation.
- **Decisions written down** as decision records, so they can be revisited rather than argued again.
- **Reviews that ask two questions:** what problem is this solving, and is this a good way to solve it.
- **Automated tests and lint rules** the team builds against, and accessibility from the start, keyboard first and audited in CI.
- **1:1s for the engineer**, not for the status report.
